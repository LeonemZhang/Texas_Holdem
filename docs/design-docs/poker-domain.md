# 扑克领域设计

## 边界

`packages/poker-core` 是无网络、无数据库、无 UI、无系统时间读取的纯 TypeScript 包。生产洗牌通过注入的安全随机源完成；测试通过注入确定性随机源和虚拟时钟复现牌局。模块按依赖顺序拆分，前置模块不能反向依赖后续模块，也不能导入协议、Socket.IO、Fastify、React、Electron 或 SQLite。

内部逻辑模块为：

1. 牌与牌组：点数、花色、编码、52 张唯一牌和洗牌输入输出。
2. 五张牌比较：牌型分类及同牌型比较键。
3. 七张牌比较：枚举 21 种五张组合并选择最大结果。
4. 座位与位置：有效座位、庄家、大小盲及双人特殊规则。
5. 下注轮状态：当前下注、跟注额、最小加注和行动资格。
6. 底池构造：贡献层、主池、边池和获奖资格。
7. 底池分配：赢家、平分、奇数筹码和未匹配贡献退回。
8. 单局状态机：翻牌前、翻牌、转牌、河牌和结算阶段推进。
9. 连续牌局状态：庄家轮转、完成局数、盲注增长和按权威座位稳定创建牌局玩家列表。

## 牌型算法

运行时从 7 张牌枚举全部 21 个五张组合，将每个组合转换为确定性比较元组，按牌型等级和逐级踢脚牌选择最大结果，返回牌型名称、比较元组和组成最佳牌型的五张牌。A2345 顺子的最高点按 5 处理。

五张牌比较元组约定如下：

```text
同花顺 [8, 顺子最高点]
四条   [7, 四条点数, 踢脚牌]
葫芦   [6, 三条点数, 对子点数]
同花   [5, 第1高牌, 第2高牌, 第3高牌, 第4高牌, 第5高牌]
顺子   [4, 顺子最高点]
三条   [3, 三条点数, 第1踢脚, 第2踢脚]
两对   [2, 大对子, 小对子, 踢脚牌]
一对   [1, 对子点数, 第1踢脚, 第2踢脚, 第3踢脚]
高牌   [0, 第1高牌, 第2高牌, 第3高牌, 第4高牌, 第5高牌]
```

运行时不依赖参考库。测试使用固定版本的成熟 evaluator 做差异验证，并覆盖全部 2,598,960 个五张牌组合的标准分类数量、固定种子七张牌强弱和平局、所有牌型、踢脚牌、公共牌成牌和 A2345 边界。引入或升级参考库时记录版本和许可证。

## 座位与下注

座位模块只输出有效座位、庄家、盲注和各街行动顺序，不读取下注状态、不推进牌局。它能跳过出局、主动退出和本局暂离座位，并处理双人局庄家兼小盲的特殊规则。

下注模块负责当前街投入、待行动集合、跟注、最小下注、最小加注、全押和短 All-in 的行动重开规则。下注轮未结束时，状态机不得因为全押或当前有筹码玩家数量变化提前 Runout；短 All-in 不重新开放已经完成行动玩家的 Raise 权利，但仍按当前合法性允许 Call 或 Fold。

## 底池与派彩

从玩家累计投入构造贡献层，再转换为主池/边池和获奖资格。弃牌者的投入进入池但不具备获奖资格；某一贡献层只有一名投入者时标记为未匹配并原样退回。每个池独立选择赢家，平分和奇数筹码从庄家左侧按顺时针处理；每个贡献层及全局结果都必须校验筹码守恒。

## 测试边界

- 纯规则测试不读取系统时钟、不访问网络和数据库。
- 牌唯一性、牌组完整性、五张/七张牌比较、座位顺序、最小加注、全押和再次加注资格必须有确定性测试。
- 主池、多个边池、平分、奇数筹码和未匹配贡献必须分别验证。
- 下注轮关闭、自动 Runout 和连续牌局编排由 `hand-lifecycle.md` 的测试负责，不能把编排逻辑偷偷放回规则原语。
