# 房间领域设计

房间领域位于 `apps/host` 的独立纯领域目录，负责多人房间规则，不连接 Socket.IO、Fastify 或 SQLite。它通过明确接口调用 `poker-core`，由应用层注入时钟、身份和持久化端口。

## 责任

- 验证房间名称、人数、初始筹码、盲注、计时、盲注增长和筹码耗尽策略。
- 处理创建、加入、座位、房主大厅换座和服务端生成的紧凑随机排列。
- 处理首局前房间准备、后续牌局准备、截止、暂离和重新就绪。
- 处理指定玩家筹码请求、主动给予、批准、拒绝、撤销和公开房间历史。
- 处理 `left`、`removed`、掉线、重连、出局和本局暂离。
- 处理房主暂停、继续、正常关闭和异常关闭语义。
- 将已确认的扑克事件归约为统计和局内称号输入，不直接计算牌型或底池。

## 设置与座位

人数范围为 2 至 10；初始筹码为正整数，首局开始后不可修改；大盲由小盲的两倍派生。大厅换座只接受房主在首局开始前对两名已入座玩家的一次原子交换；空座位不是有效目标。随机打乱由服务端生成，至少两名玩家时必须产生不同且紧凑的座位排列。

首局开始后拒绝新参赛玩家，只允许已有身份重连。双人、三人和多人庄家/盲注/行动位置由 `poker-core` 计算，房间领域只提供有效座位集合和参赛资格。

## 身份

加入后发放不可猜测的重连令牌。昵称仅用于显示并在房间内唯一，不能作为身份凭证。大厅 `left` 恢复可以原子更新昵称，局内恢复不可改名；`removed` 身份保留历史但不能继续操作或恢复。掉线、程序崩溃和网页关闭先转换为 disconnected，不删除座位、筹码、手牌记录或统计。

## 准备和筹码

首局必须由房主手动开始。后续牌局在准备阶段处理就绪、暂离、筹码请求和截止时间；存在待处理请求时不得创建下一局。筹码转移只处理双方未投入的 stack，领域变换必须原子完成并保持总量守恒。转移的公开历史保存服务端创建和最近更新时间，跨手牌、重连和恢复保留。

## 生命周期与事件

房间记录的领域状态包括 `RUNNING`、`INTERRUPTED`、`CLOSED` 和 `ARCHIVED`。同一宿主服务一次只允许载入一条运行记录。正常关闭发布最终快照和 `CLOSED` 事件；异常退出只保留最近一致快照和事件，不能写入正常关闭事件。归档改变可见性而不是删除事件、快照、玩家或统计；物理删除只允许对已归档记录进行二次确认后执行。

## 适配边界

领域服务输出可序列化结果和领域事件；应用层把它们映射到协议，持久化层在事务中保存事件和快照，客户端按玩家身份投影。房间领域不直接访问系统时钟、网卡、文件系统或数据库，使用注入的虚拟时钟和端口接口。
