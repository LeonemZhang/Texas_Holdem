# 客户端设计

客户端只消费协议快照和服务端合法行动，不自行判定赢家、底池、牌型、下注历史或牌局阶段。桌面和浏览器共享状态管理、协议模型和业务组件，运行时能力通过适配器注入。

## 模块

按交互职责拆分为：

1. 连接与重连。
2. 联机大厅、创建房间和 IP 直连。
3. 房间等待、座位和首局准备。
4. 牌桌、行动控件和牌局准备覆盖层。
5. 筹码交换、统计、结算和主动摊牌。
6. 房主管理。
7. 桌面能力适配器与浏览器能力适配器。
8. Host 管理会话与 Player 游戏会话的能力分离。

逻辑模块不等于独立 workspace 包；只有跨运行时复用或有明确部署边界时才拆包。每个功能先完成桌面和窄屏的布局定义，再接入真实服务端数据。

## 状态与投影

事件按 `sequence` 去重；发现缺口时请求补发，无法连续补发时，Player 会话接收当前玩家专属完整快照，Host 会话接收 Host 管理快照。私有信息完全使用服务端投影，客户端不接收全量底牌后再自行隐藏。客户端以相邻权威快照的 `handId`、`stateVersion` 和序列变化驱动结算折叠、音效、行动提示和筹码飞行。

## 连接与重连协调

客户端通过显式重连协调器管理初始连接、意外断开和手动恢复周期；Socket.IO adapter 关闭内置自动重连。每个周期固定使用 `500 ms` 间隔和最多 `20` 次尝试，自动周期达到上限后只进入手动模式；手动重试会取消旧计时器、连接 Promise 和监听，再使用完全相同的参数启动新周期。协调器为每次 Socket 和尝试分配 generation/attempt ID，旧实例的连接结果、错误、断开事件和快照不能污染当前实例。

连接状态机区分连接中、已连接、恢复中、失败和主动断开；`connected` 只表示 transport 已连通，不代表业务恢复。Player 牌桌必须收到 `roomId`、`playerId` 匹配且 `sequence >=` 当前快照的权威 `state:snapshot` 才解锁下注和玩家操作；Host 控制台必须收到 `roomId`、`hostId` 匹配且序列不倒退的 Host 管理快照才解锁房主管理。快照等待约 `10 s` 超时后当前周期进入手动失败终态；`closed`、`removed`、主动离开、组件销毁和协调器停止都释放 Socket、计时器和监听，不再重连。

恢复期间不自动重发任何未确认命令。接受恢复快照时不把断线期间的历史状态当作相邻变化，不重播音效、结算展开或筹码飞行动画；恢复完成后只从后续相邻权威快照产生反馈。客户端不要求 Host 增加 `connectionStateRecovery`，也不改变服务端权威性、协议幂等或 SQLite 契约。

手机座位队列与桌面座位坐标分离：桌面位置按固定 `seatIndex` 计算，手机队列始终包含房间快照中的全部玩家，并以 `handId + street` 为边界按服务端行动顺位重排；同一轮只调整滚动位置，不改变节点顺序。本人在队列中使用不可交互但内容一致的摘要卡，真实本人座位仍固定在牌桌下沿。

## 页面与布局

- 牌桌分为顶部状态、中间牌桌工作区和底部操作区；工具面板由页面统一仲裁，同一时间只显示房主管理、筹码交换或统计中的一个。
- 桌面使用右侧工具抽屉，手机使用全屏工具面板；三类工具共用吸顶头部和单一收起动作，工具打开时隔离下注区和加注弹层，关闭后恢复加注草稿。
- 正常对局的公共牌、底池纵列和本人底牌相对桌布水平居中；结算详情通过共享标签列使公共牌、玩家底牌和最佳五张牌实际卡牌左边界对齐。
- 底池统计行在桌面端按全部统计标签整体宽度展开并保持其外接矩形中线与公共牌中线对齐；移动端统计窗口复用第一张公共牌左边缘至第五张公共牌右边缘的宽度，默认采用紧凑间距，仍溢出时按整体宽度等比缩放并重新居中，最后保留横向滚动。
- 结算卡片自身管理折叠状态，标题行使用独立收起按钮，不复用工具抽屉头部；新 `handId` 自动展开。当前筹码、净变化、牌型和公开牌面全部直接渲染服务端投影。
- 牌桌等待页按权威 `seatIndex` 和 `maxPlayers` 投影物理座位；房主拖放只提交一次权威换座命令，空位不接收拖放，随后等待房间快照，不做乐观排序。
- 首局开始后新加入玩家仍显示在权威牌桌玩家列表中，但在当前牌局中显示“等待下一局”，不渲染本人底牌、行动按钮或当前局投入；牌局准备阶段沿用所有玩家相同的“就绪”操作，服务端投影其 `handReady.ownChoice` 为 `pending`，只有服务端确认 `ready` 后才进入下一局参赛者。
- `仅提供服务` 模式的 Host 控制台不渲染房主玩家卡片、房主筹码或房主准备状态；玩家视图仍只渲染实际玩家座位。
- `仅提供服务` 模式的 Host 控制台可进入只读观战牌桌；观战牌桌复用正式牌桌布局，渲染 Host 管理快照中的公共牌、底池、玩家投入、行动者、行动倒计时和已公开摊牌结果，不渲染玩家下注、筹码交换、准备控件、未公开底牌或 `legalActions`。
- 仅提供服务的 Host 大厅复用 `LobbyWaitingRoom` 的玩家列表、座位拖放、配置、随机打乱、邀请分享和准备统计布局，但不注入 Host 玩家卡片；“加入观战”与“开始游戏”并列在大厅左下角。首局开始后 Host 默认切换到观战牌桌，观战牌桌右上角的房间管理旁提供返回大厅入口。
- 参与游戏牌桌和观战牌桌的房主管理都通过同一工具面板提交 Host 命令；首局未开始时配置编辑器隐藏当前小盲，首局开始后回填并显示当前小盲，锁定基础小盲、初始筹码和人数上限。局内当前小盲的最小值为基础小盲，填写小盲上限后最大值同步为该上限；输入完成时统一归一化，允许房主编辑下一局当前小盲及服务端允许的动态字段，客户端不自行判断动态设置的生效时间。

## 行动控件

加注草稿金额始终夹在服务端下发的最小和最大合法值之间。快捷比例 `1/4`、`1/3`、`1/2`、`2/3`、`3/4`、`全部` 使用本人快照中的本轮剩余筹码计算追加目标，比例点击只修改草稿，确认按钮才提交 `game.raise-to` 意图。手机调整和确认是两个持续可达的动作；视觉筹码盘可以缩小，但触控区保持至少 44×44 CSS 像素。

## 反馈与预览

筹码飞行只由相邻权威快照确认的投入增长触发，起点为玩家卡片主体中心，动画不参与筹码计算。音效只从新确认的状态变化触发；首次快照、重复快照、重连和回放不补播历史。行动读秒只消费当前玩家和服务端截止时间，并在行动完成、截止、换人或组件销毁时清理调度。

开发预览和视觉 smoke 入口只能组装正式页面/业务组件并复用正式 CSS class 与响应式规则；禁止在预览入口或全局样式中增加只为预览存在的视觉样式，不以静态 mock 形成第二套牌桌外观。
