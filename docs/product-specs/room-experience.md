# 房间体验产品规格

本文描述玩家可观察到的房间、加入、座位、筹码、离开和恢复行为，不描述 LAN discovery、Socket.IO、IP 解析或其他 transport 细节。

## 角色与入口

- 房主必须使用 Windows 客户端创建房间并入座参与游戏，不提供仅管理员模式。
- 房主可以设置房间规则、开始首局、暂停、继续、移除玩家和关闭房间；房主筹码耗尽后仍可管理和观战，但重新获得筹码后才能参赛。
- 普通玩家可以使用 Windows 客户端或手机/电脑浏览器参加完整游戏，但不能修改房间规则或替代房主裁决。
- 浏览器玩家通过房主提供的地址或二维码进入。进入后必须先检测房间可连接，再输入昵称并确认加入。
- 浏览器不能创建房间或主动扫描局域网房间。

Windows 客户端首页提供创建房间、刷新可加入房间列表和手动输入房主地址三个入口。房间列表展示房间名称、房主、人数、状态、初始筹码、盲注、延迟和版本兼容状态。点击可加入房间后直接打开昵称输入弹窗；确认后才检测并提交加入，不要求玩家返回首页重新输入昵称。大厅阶段退出的玩家再次进入同一房间时，昵称以原值预填但允许修改；确认恢复必须复用原令牌、`playerId` 和座位，不得创建第二身份。进行中的房间遵循局内恢复规则。

## 房间设置

- 最少 2 人、最多 10 人；人数上限不得低于当前大厅玩家数。
- 房主可配置初始筹码、盲注、盲注增长、行动时间和筹码耗尽策略；字段合法值、计算公式、超时行为和增长时机统一由[玩法规格的盲注与筹码](gameplay.md#盲注与筹码)定义。
- 首局开始后不能再修改初始筹码；其他设置是否允许修改以当前房间阶段和服务端权限校验为准。

创建房间和首局开始前，房主可修改房间名称、人数上限、初始筹码、盲注、计时、盲注增长和筹码耗尽策略。盲注增长提供“不增长”“倍率增长”“步长增长”三个互斥模式；“不增长”时增长参数不生效，另外两种模式只按当前选中的参数计算。输入过程中表单保持可提交：步长和小盲上限不得低于当前小盲，输入较小值立即提升；小盲调整后已填写参数立即提升；空的小盲上限表示不设上限。大盲上限为只读值，始终等于小盲上限的两倍。配置通过服务端命令生效，并由最新房间快照同步给所有玩家；修改初始筹码时同步大厅玩家余额，但不改变准备状态。

## 座位与首局

等待页按当前人数上限展示对应数量的物理座位；桌面与手机的具体排列、空位展示和滚动行为由[桌面与响应式体验](desktop-experience.md#联机大厅与房间等待)定义。

首局开始前，房主可以把一个已入座玩家卡片拖到另一个玩家卡片上，以一次权威命令原子交换两人的座位；空座位不可作为拖放目标，也不提供另一个“调整座位”按钮或弹窗。若座位出现空洞，先使用服务端生成的“随机打乱”恢复从座位 1 至 N 的紧凑排列，随机结果在至少两名玩家时必须不同于当前顺序。客户端等待房间快照后更新，不做乐观排序。

房主默认已准备，其他玩家必须主动准备；至少两人且所有非房主玩家准备后，房主的“开始游戏”按钮才可用。首局开始后不接受新的参赛玩家，只允许已有玩家重连。首局开始前的座位交换、随机排列和规则修改不改变玩家准备状态、筹码、身份或权限。

## 筹码交换

筹码请求只能在牌局准备阶段创建；主动给予也只在牌局准备阶段发起。已创建请求可跨阶段批准、拒绝或撤销。已投入当前局底池的筹码不能转移；对局中只转移双方未投入的可用筹码。

- 主动给予必须指定接收玩家、数量并二次确认，系统先展示转移后的双方余额。
- 请求者必须指定一个目标玩家，不提供面向全桌的请求；请求包含期望数量和可选说明。
- 请求不能超过目标玩家当前可转出的筹码。允许给予者转出全部可用筹码，但必须显著警告其无法参加下一局。
- 每次转移原子扣减给予者并增加接收者；余额不足时双方不变。
- 待处理、成功、拒绝、撤销和主动给予进入按最近更新时间排序的公开房间记录，跨牌局、重连和服务恢复保留。
- 玩家筹码总量在转移前后保持不变，筹码交换不计入牌局净输赢。

## 离开、掉线与重连

### 普通玩家主动退出

Windows 客户端关闭或牌桌退出入口显示“是否退出房间？”确认框，默认操作为“退出房间”，另一操作为“取消”。确认后统一记为 `left`，保留历史、统计、筹码、座位和原设备恢复身份；该座位不计入大厅人数、准备人数或后续牌局，也不清除原设备恢复令牌。

同一设备再次进入时必须凭保存的恢复身份回到原玩家状态，不重新发放初始筹码；其他设备不能仅凭相同昵称恢复。若退出发生在当前局，服务端沿用行动超时逻辑，能过牌就过牌，否则弃牌；恢复后该玩家本局暂不参与。大厅阶段恢复可修改昵称，局内恢复不可改名；昵称冲突时恢复失败并保留表单。玩家离开房间 A 后可以加入房间 B，两间房间的身份、筹码和统计彼此独立，A 的恢复资格继续保留。

网页玩家必须使用游戏内“退出房间”按钮表达主动退出。普通刷新、网络中断、程序崩溃和网页标签关闭都先视为意外掉线，不删除玩家、筹码、座位、手牌记录或统计；掉线期间轮到该玩家时按行动超时规则处理，恢复后回到原座位。

### 意外掉线的客户端恢复

初始连接、普通刷新、程序崩溃、网络中断和网页标签关闭都必须使用保存的房间身份尝试恢复；意外断开后客户端立即显示“连接中断，正在恢复”，并锁定下注、筹码交换、房主管理和其他外部操作。自动恢复按固定 `500 ms` 间隔最多尝试 `20` 次，不逐次延长间隔，也不自动开始第二个周期；达到上限后显示可操作的手动重试入口。

手动重试使用同样的固定 `500 ms` 间隔和最多 `20` 次尝试，开始新周期前取消旧的等待和连接操作；重复点击不能产生并行周期。Socket 或网络重新连通不等于恢复成功：只有收到当前房间、当前玩家身份匹配且序列不倒退的权威房间快照，才清除恢复提示并重新开放操作。恢复前不自动重发尚未确认的命令，恢复后的操作必须基于当前权威快照重新发起。

连接成功但在约 `10 秒` 内没有收到可接受的权威快照时，当前周期进入失败终态并停止自动尝试，用户可再次手动重试。收到房间已 `closed` 的权威快照后按正常结束流程展示结果，房主随后主动断开不显示网络异常；收到本人已 `removed` 的权威快照后退出当前房间并停止恢复。无法匹配房间或玩家身份的快照不能解锁操作，也不能让客户端永久停留在恢复中。

### 房主移出与关闭

- 房主移出玩家统一记为 `removed`；被移出玩家保留座位、昵称、筹码、统计和历史，但牌桌视觉列表不显示该玩家。首局开始后只能在牌局结束后的准备阶段移出。
- 被移出玩家在房间关闭前不得再提交命令或恢复身份，但仍可加入其他房间。
- 房主不能把自己当作普通玩家退出。关闭房间前显示“是否关闭房间及当前对局？”确认框，确认后保存最终结果、通知其他玩家，等待最终快照送达房主客户端后停止宿主服务并释放端口。

## 房间与记录生命周期

每次创建房间都创建独立对局记录，包含房间设置、房主、创建时间、最后活动时间、生命周期状态、最终统计、恢复快照和事件。记录状态为：`进行中`、`异常中断可恢复`、`正常结束`、`已归档`。同一台房主电脑同时最多运行一场对局。

- 房主客户端启动后进入牌桌大厅，不自动加载旧房间。
- 检测到本机仍运行的房主服务及其“进行中”记录时，在“IP 直连到房主牌桌”上方显示对局摘要和“恢复对局”按钮。
- 记录摘要和恢复表单展示该局保存的网卡与 IPv4。恢复时优先复用仍属于本机的保存网卡；保存网卡缺失或已失效时，房主必须重新选择可用网卡后才能恢复。
- 异常中断记录由房主明确选择恢复；正常结束记录可查看和归档。归档只从默认列表隐藏，不删除历史；只有已归档记录能在展示对局名称和不可恢复警告后，经二次确认物理删除。
- 记录管理页提供查看统计入口，复用局内统计标签页，不向局域网或浏览器开放。
- 房主在已有进行中记录时创建新房间，必须先选择恢复旧局，或按正常关闭流程关闭旧局后创建新房间；不能覆盖其他可恢复记录。
- 房主异常退出不标记为正常关闭，不支持其他设备接管房主；同一台房主电脑重新启动后也不自动恢复最近一局。
