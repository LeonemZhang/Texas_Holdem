# 桌面与响应式体验产品规格

本文描述可观察的 Windows、浏览器和响应式体验。Electron 实现边界见 [`docs/design-docs/desktop.md`](../design-docs/desktop.md)。

## Windows 客户端

- 房主必须从 Windows 客户端创建房间；普通玩家可以使用 Windows 客户端或浏览器加入。
- 主窗口以 1920×1080 为目标的普通窗口启动，并按启动显示器工作区裁剪安全尺寸，保留最小化、最大化、还原和关闭能力。
- 不使用独占全屏、Kiosk、无边框窗口或固定分辨率。
- 原生 1920×1080、Windows 100% 显示缩放和目标窗口尺寸是桌面最低支持基准；更低分辨率、低高度窗口或更高缩放只作尽力兼容，允许纵向滚动或紧凑布局，但不阻止进入房间、加入游戏，也不显示分辨率提示。
- 可执行文件、原生窗口、任务栏、任务管理器进程组、桌面与开始菜单快捷方式、安装和卸载入口统一使用 `Texas Holdem` 产品名和德州扑克品牌图标，不回退为 Electron 默认名称或图标。
- SQLite 对局记录、Electron 本地状态和缓存统一位于系统应用数据目录的 `Texas Holdem` 子目录，不在桌面创建运行数据目录，也不接受外部启动参数把运行数据重定向到桌面。

## 浏览器品牌与连接

浏览器标签页、收藏夹、Web App manifest、系统磁贴和二维码使用与 Windows 客户端一致的产品名、主题色和品牌图标；通过房主 HTTP 服务访问和 Electron 本地加载时使用同一来源生成的资源。

房主创建或管理房间时能看到当前选择的网卡、对外公布的 IPv4、游戏端口、发现端口、防火墙提示、可复制连接地址和二维码。广播发现只是便利功能，手动输入房主 IP 或完整地址始终独立可用。多网卡场景中，展示给玩家的可达地址以实际响应来源为准，不被其他接口的宣传地址覆盖。

## 联机大厅与房间等待

- 联机大厅提供创建房间、刷新房间列表和 IP 直连；扫描牌桌和网络诊断进入独立页面，并可返回大厅。
- 桌面房间等待页使用固定两列五行座位表，左列座位 1–5、右列座位 6–10，空位仍展示；手机只展示实际玩家的单列滚动列表。
- 座位操作只提供首局前的拖放交换和服务端“随机打乱”。房主开始与普通玩家准备入口靠左排列，不能出现空座位拖放目标或另一个调整座位弹窗。

## 牌桌与结算

- 桌面牌桌使用顶部状态、中间牌桌和底部操作三个稳定区域；牌桌约 16:9、最大 80rem，底部操作区限制在约 72rem，十人局使用专属紧凑座位密度。
- 正常对局中，牌局进度、独立倒计时、公共牌、底池纵列和本人底牌按独立流式行排列；公共牌、底池和本人底牌相对牌桌水平居中且不得互相遮挡。过长进度单行省略，但完整文本仍可通过可访问名称读取。
- 总池始终显示；本局下注历史按翻牌前、翻牌、转牌、河牌纵向排列，当前街实时更新，已结束街固定显示最终金额。牌桌状态行显示当前有效盲注。
- 座位卡显示玩家、筹码、当前下注、状态、倒计时、庄家/盲注标记、本轮投入和本局累计投入，但不展示底牌。正常对局时本人底牌在牌桌中央；结算时牌桌中央隐藏公共牌、底池和所有底牌，结算框顶部展示已公开公共牌、总池和已发生街道记录。
- 本人拥有至少五张可用牌时显示服务端计算的当前最佳牌型，少于五张时不虚构牌型；结算只展示服务端授权的牌型和最佳五张牌。
- 结算框展示每位玩家的当前权威筹码、本局净变化、已授权底牌或背牌和最佳五张牌；公共牌、底牌和最佳五张牌使用相同标签列，使实际卡牌左边界一致。标题只显示本人对应的“胜利”“失败”或“平局”，本人结果固定首位并显示“我”，其他玩家顺序保持服务端顺序。
- 结算通过卡片内部“本局结算 + 收起”标题行折叠，收起按钮使用独立的青绿色描边胶囊样式，不复用工具抽屉头部；桌面和手机入口均在牌桌中央进度文字正下方，新 `handId` 自动展开。收起后恢复原牌桌公共牌、底池、本人底牌和当前牌型。
- 结算准备框顶部操作按“就绪”、主动“摊牌”、“本局暂不参与”组织；主动摊牌入口紧随就绪操作，至少保留 44px 点击区域。服务端确认后，结算框展示公开底牌。

## 行动与反馈

- 提供弃牌、过牌、跟注、下注、加注和全押；跟注按钮中的金额与文字不得换行。
- 桌面端跟注按钮始终显示“跟注 + 金额”；本人不需跟注时金额显示为 `0`。服务端快照使跟注不可执行时，按钮保持不可点击并使用灰化/降饱和样式。
- 加注条提供 `1/4`、`1/3`、`1/2`、`2/3`、`3/4`、`全部` 六个等宽比例快捷段，按本人权威快照中的本轮剩余筹码计算追加目标，并夹在服务端最小和最大合法加注之间。比例点击只更新草稿，确认按钮才提交命令；滑块和筹码微调保留。
- 手机端将加注拆成“调整加注到”和“确认加注到”；未调整时确认最小合法加注。弹层不得遮住确认入口，视觉筹码盘可以缩小，但触控区不小于 44×44 CSS 像素。
- 已确认的同手筹码投入只根据相邻权威快照中的投入增长播放从玩家卡片主体中心飞向总池的动画，持续不少于 1.5 秒，筹码面额随金额显示；动画不参与筹码计算，并支持减少动态效果偏好。
- 发牌、牌局准备、轮到自己或其他玩家、下注、弃牌和结算输赢/持平等已确认状态变化提供简短音效。首次进入、重连和回放不补播历史音效。只有轮到本人且服务端提供有效截止时间时播放“滴→答”提示；换人、行动完成、截止或离开牌局后立即停止。

## 响应式要求

- 最低支持 360 CSS 像素宽度，手机竖屏能完成全部游戏操作，不要求切换横屏。
- 主要触控目标至少 44×44 CSS 像素。手机操作区固定在底部并避开地址栏、底部工具栏和安全区。
- 打开统计、筹码交换或房主管理时隐藏下注区和加注弹层；工具内容可滚动到底部，关闭后恢复此前的加注草稿。
- 桌面统计抽屉的牌型记录始终将完整五张牌放在同一行；可用宽度不足时缩小牌面，不能换行或出现横向滚动。
- 手机顶部行动队列始终包含权威快照中的全部玩家。每局及每条街开始时按服务端行动顺位重排，同一轮内保持顺序不变；当前行动者变化时只调整滚动位置，使已行动玩家保留在左侧、待行动玩家在右侧。右侧玩家已能完整显示时，不通过队尾空白强制贴左；本人使用不可交互但内容一致的摘要卡，真实本人座位仍固定在牌桌下沿。
- 筹码交换、统计和房主管理共用统一工具抽屉头部和单一“收起”按钮；桌面使用右侧抽屉，手机使用全屏面板，同一时刻只显示一个工具面板。
- 普通玩家退出入口位于桌面和手机牌桌顶部工具栏最右侧，与筹码交换、房主管理和统计同层。工具按钮组可横向滚动，退出入口不可收缩或被结算层覆盖。默认显示至少 44×44 的“×”，首次点击在原位置展开“退出房间”，再次点击才显示确认；外部点击、Escape 或取消后恢复为“×”。
- 桌面端总池与街道统计行按内容向右展开，并保持统计区域中线与公共牌中线对齐；移动端统计窗口宽度与公共牌五张牌总宽度一致，内容超出时先收紧标签间距并等比缩小整行，仍不足时允许横向滚动。
- 任何关键状态不能只依赖鼠标悬停；响应式判断使用浏览器或 Electron 的实际可用视口，桌面不假定固定任务栏高度。

## 桌面安全与数据目录

Electron renderer 必须保持 sandbox、context isolation 和 `nodeIntegration=false`。桌面能力只能通过窄化且参数校验的 preload API 暴露；桌面不加载远程房主 HTML，外部链接交给系统浏览器；运行数据不得被外部参数重定向到桌面。
