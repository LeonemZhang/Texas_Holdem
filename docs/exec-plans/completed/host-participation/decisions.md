# 房主参与模式计划决策

## 已确认

- 每个房间创建时选择 `参与游戏` 或 `仅提供服务`，创建后固定。
- `仅提供服务` 的房主不占座、不获得筹码、不进入准备人数、行动顺序、底池、牌局统计或玩家人数上限。
- 首局至少需要两名实际玩家，且所有实际玩家准备完成；房主只负责手动开始。
- Host 身份和 Player 身份分离，分别使用 Host 恢复令牌和 Player 恢复令牌。
- Host 控制台只消费 Host 管理快照；服务端不把玩家专属快照广播给 Host UI。
- Host 控制界面断线但服务进程仍运行时，房间继续服务；Host 进程异常退出时进入异常中断。
- 只支持原房主设备恢复，不支持其他设备接管，不支持多管理员或 Host 委派。
- 旧记录缺少参与模式或 Host 身份时默认按 `参与游戏` 恢复，不自动转换。
- 浏览器只能作为 Player 加入；Android/mobile 继续遵循 ADR-007 的普通玩家边界。
- 本计划只增加 LAN Host 的房间角色能力，不实现中心服务器，不同步两种部署模式的记录或身份。
- 不在用户界面或产品文案中显式展示“房主设备是受信任服务端”的安全提示；该边界只作为内部架构和测试约束保留。

## 实现约束

- 不把 `hostPlayerId` 改成可空字段后继续复用旧权限路径；领域模型必须拥有独立 Host 身份。
- 不创建不可见的虚拟房主玩家；玩家集合、座位、筹码、准备和统计必须只由实际玩家组成。
- 新 Host/Player 身份和 Host 管理快照必须通过 `packages/protocol` schema 校验，不能用 `any`、宽泛对象或客户端本地推断绕过。
- 新协议需要明确兼容边界；v3 旧记录按参与游戏模式恢复，服务型房间不能静默降级为旧 Player 会话。
- 任何实现任务开始前，重新检查并行计划对同一文件的修改，按 hunk 精确保留无关变更。
