# ADR-010 — 首局开始后新玩家等待下一局参赛

## 背景

房间首局开始后，继续允许新的 Player 身份加入可以降低临时组局的等待成本，但当前牌局已经创建了参与者、底牌、投入、行动顺序和底池。把新玩家直接注入当前牌局会改变扑克规则边界，也会破坏已有玩家看到的权威快照和结算结果。

## 决策

未关闭房间在首局开始后继续接受新的 Player 身份。新玩家获得唯一身份、座位、初始筹码和 `waiting` 状态，但不加入当前已创建牌局：

- 牌局进行中加入的玩家等待下一次牌局准备阶段。
- 在 `hand-ready` 阶段加入的玩家进入当前准备上下文，选择默认为 `pending`。
- 新玩家必须主动选择“已就绪”，并满足当前有效大盲、待处理筹码请求和至少两名已就绪玩家等既有准备条件，才进入下一局参赛者集合。
- 加入不会改变当前牌局参与者、底牌、投入、行动顺序、底池、Runout 或结算。
- 房间关闭后仍拒绝新玩家加入；已有玩家的恢复令牌、座位、筹码、历史、主动退出、掉线和移除语义不变。

该决策不引入当前手中途入局，也不新增独立观战者角色；等待中的新玩家仍是房间中的普通 Player 身份，并通过权威快照看到自己等待下一局的状态。

## 影响

Host 的加入校验和牌局准备上下文需要区分“已进入房间”和“当前局参赛”；客户端需要在当前牌局缺少本人手牌时展示等待下一局，而不是误判为恢复失败。协议沿用现有玩家列表、状态和 `handReady` 字段，不增加协议版本或 `poker-core` 算法。
