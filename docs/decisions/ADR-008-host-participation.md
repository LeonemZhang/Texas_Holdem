# ADR-008 — 房主参与模式与玩家身份分离

## 背景

现有房间把房主身份和第一个玩家身份绑定在一起。该模型无法表达“房主只提供房间和服务、不参加牌局”，并会把房主错误地带入座位、筹码、准备、统计和玩家快照。

## 决策

每个房间创建时固定一种房主参与模式：`参与游戏` 或 `仅提供服务`。

房主使用独立的 Host 身份和恢复令牌，玩家使用独立的 Player 身份和恢复令牌。`仅提供服务` 模式不为房主创建玩家座位、筹码、准备状态、行动资格或玩家统计；房主管理会话使用独立的管理投影，不复用玩家专属快照。Windows Host 控制台可从管理投影进入只读观战牌桌，显示公共牌桌、行动和已经公开的摊牌结果，但不显示未公开底牌、`legalActions` 或玩家操作控件。

现有房主参与模式继续兼容：一个本地创建流程可以同时建立关联的 Host 身份和 Player 身份，但领域和协议不再把二者视为同一身份。旧记录默认按 `参与游戏` 模式恢复，不自动转换为 `仅提供服务`。

本决策首期只覆盖现有 Windows Host。浏览器只能作为玩家加入；Android/mobile 继续遵循 ADR-007，不因本决策获得 Host 能力。LAN Host 与未来可能的中心服务器属于独立部署模式，本决策不引入中心服务器或跨设备记录同步。

## 影响

- 房间人数、座位、准备门禁、筹码和统计只针对实际玩家计算。
- Host 控制命令必须通过 Host 会话授权，不能继续依赖 `hostPlayerId` 作为唯一权限凭证。
- 协议需要区分 Host 管理会话和 Player 游戏会话，并提供不包含玩家私有信息的 Host 管理投影。
- SQLite 需要保存房主参与模式和 Host 恢复身份；旧记录按兼容默认值读取。
- Host 控制界面断线不关闭仍在运行的服务；Host 进程异常退出仍进入异常中断，不能由其他设备接管。
