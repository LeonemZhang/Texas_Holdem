# ADR-009 — 房主动态房间配置的字段与生效边界

## 背景

房主需要在牌局开始后根据实际牌局节奏调整行动时长、下一局准备等待时长和盲注增长等房间配置。房主可能参与游戏，也可能使用独立的 Host 管理会话；两种模式都必须遵守同一套服务端权限和生效规则。当前牌局已经创建了盲注、底池、筹码和绝对截止时间，不能因为设置编辑而被客户端或服务端回算。

## 决策

房主在房间未关闭期间均可通过房主管理入口提交设置修改，不受房主是否参与游戏影响。修改必须经过 Host 身份、`expectedVersion` 和完整设置 schema 校验，并通过最新权威快照同步给 Player 与 Host 客户端。

首局开始后允许动态修改：

- 房间名称；
- 行动时长；
- 下一局准备等待时长；
- 下一局当前小盲；
- 盲注增长的启停、间隔、模式、倍率/步长和上限；
- 筹码耗尽策略。

首局开始后禁止修改：

- 初始筹码；
- 人数上限；
- 基础小盲。

首局开始后允许单独指定当前小盲；该值代表下一局的权威有效级别，不是基础配置覆盖。当前正在进行的牌局继续使用已经创建的盲注。

生效边界如下：

- 房间名称和筹码耗尽策略在服务端接受命令后用于后续判定；
- 行动时长不重算当前行动者已经启动的截止时间，新值从下一次行动截止时间开始使用；
- 牌局准备等待时长不重算当前准备窗口的截止时间，新值从下一次准备窗口开始使用；
- 房间状态分别保存基础小盲、权威当前小/大盲和下一次增长阈值。盲注增长参数不改变当前牌局或已经保存的当前级别；当前小盲修改从下一局开始，增长从该级别继续，不按基础小盲和已完成局数回算历史；倍率、步长和上限修改保留已排定的下一次增长，下一次增长完成后才以新间隔安排后续增长；
- 任何设置修改都不能回算当前牌局的盲注、底池、玩家筹码、行动结果或已发布结算。

参与游戏的房主和仅提供服务的房主使用相同的房间管理能力。仅提供服务的房主大厅复用参与游戏时的玩家列表布局；首局开始后默认进入观战牌桌，观战牌桌的房间管理入口与“返回大厅”并列放置在右上角。

## 影响

- `room.update-settings` 不再只限于大厅阶段；领域层按字段和房间阶段执行上述门禁。
- 调度器继续使用已经持久化的当前截止时间；后续新建任务读取最新设置。
- 盲注增长必须在下一局创建前读取最新配置，不能在当前手中更换盲注。
- Host 管理快照需要在大厅和牌桌阶段都提供房间设置，客户端只提交编辑结果，不自行决定生效时机。
- 初始筹码、人数上限和基础小盲的编辑控件在牌局开始后应禁用或隐藏；当前小盲使用独立编辑控件，并仍由服务端拒绝越权请求。
